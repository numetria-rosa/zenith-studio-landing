Cross-module challenges

Two scenarios that don't belong to any single module. Both require combining context budgeting, retrieval, tool idempotency, agent control flow, reliability, and evaluation, the same way a real production AI system does. Pass both to unlock the capstone.

1

Reliable RAG Support Bot

You're designing a retrieval-augmented support bot for a client. Make the calls a senior AI engineer would actually have to make.

System under design
User query→Retrieval (embed + search)→Context assembly→Model call (with tools)→Tool execution→Response

Known failure modes you must design around: retrieved content exceeding the token budget, model API rate limits under load, a tool call retried after a lost response, an agent loop repeating the same search without progress, and low-relevance chunks getting forced into context anyway.

Context budget
Retrieved chunks for a query total 7500 tokens. The context window is 8000 tokens, with 1500 reserved for output. What should happen?
Reliability
Mid-conversation, the model API returns a 429 (rate limited). What should the bot do?
Tool use
The bot calls a create_support_ticket tool; the network drops the response after the ticket was actually created server-side, and the agent retries with the same call ID. What should happen?
Agent control flow
The bot's agent loop calls search_kb with the exact same query three times in a row without making progress. What should the loop do?
Retrieval quality
The relevance threshold is set at cosine similarity 0.4. The top result for a query scores 0.22. What should the bot do?
Evaluation
After tuning the retrieval top-k value, how do you know whether the change actually helped, before shipping it?
