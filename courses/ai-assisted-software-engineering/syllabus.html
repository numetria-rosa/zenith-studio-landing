Syllabus

Fourteen Northline Digital tickets. You write the spec, inspect what an agent produced, run it, test it, review it, and ship it. Hand-writing comes before agent work. Prompt engineering sits after the web modules and before Cursor.

This is not AI Engineering. That course builds LLM products (RAG, tools, eval) and assumes programming logic. This course starts at zero and ends at a live web app you specified, reviewed, tested, and shipped with Cursor and GitHub.
Access. On zenith-studio.site, course files are served only after sign-in and a Whop entitlement. Opening this folder on disk is for authors. Duplicate payment webhooks do not double-grant. This syllabus cannot run a live card payment. Entitled paying-user click-through was not independently re-run in this audit (needs a real login and a real card). Anonymous production probes: unpublished courses 404; signed-out hits on published modules redirect to sign-in; the catalog landing stays public.
Accessibility. Practical checks: skip link, role="main", labelled forms, visible focus, aria-live on graders, Escape closes the nav drawer, 320–1440px overflow. Not a WCAG certification. Screen-reader behaviour (NVDA / VoiceOver) is not independently certified.
00

What you will be able to do

Specify a small web feature, write an engineering prompt an AI coding assistant can be supervised against, drive Cursor, read the diff, write and run tests, open a GitHub PR, and deploy a live https URL. You will not be a senior engineer. We do not guarantee a job.

01

Modules

  1. 0 Orientation. The eleven-step loop, Northline Digital, an honest self-check. Everyone still starts at Module 1. Nothing here locks.
  2. 1 NL-001 — Your first shipped change. Read a ticket, change one line of HTML, render it, write a commit message a colleague would accept.
  3. 2 NL-002 — Requirements. Turn “make it better” into stories, acceptance criteria, edges, and an out-of-scope list. Specs practice is a labeled multiple-choice simulation.
  4. 3 NL-003 — HTML structure. Landmarks, forms, labels. Catch the agent’s div soup.
  5. 4 NL-004 — CSS that survives a phone. Box model, flexbox, one breakpoint you can defend.
  6. 5 NL-005 — JavaScript you can defend. Predict, catch the agent’s filter, then write filterOpen and countFor yourself.
  7. 6 NL-006 — DOM, events, late data. Four UI states (loading / empty / error / data). We grade those states and a real click handler, not a live fetch.
  8. 14 NL-014 — Prompt Engineering for Software Engineers. Turn vague requests into Context → Task → Constraints → Acceptance → Verify. Five graded prompt labs plus a Northline invoice challenge. Not ChatGPT tricks. Unlocks before Cursor so you can use the skill in later labs.
  9. 7 NL-007 — AI as your pair programmer. The full loop in Cursor. You bring the output back; we run tests against it. Desktop Lab A starts here.
  10. 8 NL-008 — AI Code Detective. Plausible AI code with real defects mixed with innocent lines. Find them, then prove the fix.
  11. 9 NL-009 — Testing and debugging. Write a test that can fail. “Works on my machine” is a starting point, not a defence.
  12. 10 NL-010 — Git, GitHub, and review. Branch, diff, PR. In-browser git/review libraries are labeled simulations. Desktop Lab B: a repo you own.
  13. 11 NL-011 — Refactoring, security, maintenance. Change the shape without changing behaviour. Then find the leak.
  14. 12 NL-012 — Python for scripts. Enough Python to kill a Monday chore. Not RAG. Not agents.
  15. 13 NL-013 — Release and ship. Live URL (not a github.com repo), tests, release notes, rollback plan. Capstone briefs on Projects.
02

Gates

From Module 2 onward a module unlocks only after the previous module in sequence has its checkpoint quiz ≥80% and its required exercise done. NL-014 sits after Module 6 and before Module 7. Completed tickets stay completed if you already finished 7–13 before this module existed. Module 13 also needs 3+ passed tasks in at least three of four tracks (HTML, CSS, JavaScript, AI Code Detective) plus both Desktop Labs. Lab A’s commit URL is optional; the notes carry the evidence. Lab B requires a GitHub repo URL.

03

What we will not do

  • No in-browser fake Cursor that “runs the agent.”
  • No AI tutor that does not exist.
  • No invented task counts on the public catalog until a verifier agrees.
  • No job guarantee. Career page lists the gaps: algorithms, systems design, incident ownership, team process.
04

What this course can and cannot verify

Can verify (platform): module checkpoints, in-browser graders, judgment labs (including simulations), required field length, GitHub API when it answers, live-URL shape when CORS allows.

Can partially verify (artifact): a public repo exists; a URL is https and not github.com/localhost/example; an obvious parked page if the body is readable.

Cannot verify: that Cursor was open; that an arbitrary live app is high quality; professional employment; real production on-call; WCAG certification; NVDA/VoiceOver behaviour; a live card payment in this syllabus tab.
