00

Why this matters

01

Before you touch AI

A page is a document, not a picture. The browser builds a tree from your tags, and everything else — how it looks, how a screen reader announces it, how a keyboard moves — hangs off that tree.

The criterion for which element to use is not "which one looks right". None of them look like anything without CSS. The criterion is which one means what you are trying to say.

Semantic HTML

<nav> and <div class="nav"> can render identically. Only one of them tells every other piece of software that this is the navigation.

03

The landmarks, and the form everyone skips

<body>
  <header>
    <nav><!-- primary links --></nav>
  </header>
  <main>
    <h1>Northline Clinic</h1>
    <section>
      <h2>Opening hours</h2>
    </section>
  </main>
  <footer></footer>
</body>
  • One <main> — the unique content of this page. Screen reader users jump to it.
  • One <h1>, then headings that descend in order. Size is CSS's job.
<form>
  <label for="email">Email address</label>
  <input type="email" id="email" name="email" required>
  <label for="date">Preferred date</label>
  <input type="date" id="date" name="date" required>
  <button type="submit">Request appointment</button>
</form>

label for names the field and makes the words clickable. type="email" gets the right keyboard on a phone. required stops empty submit with no JavaScript. A placeholder is a hint that leaves; a label stays.

Four accessibility rules that cover most of this page
  1. Real controls. <button> for actions, <a href> for navigation. A <div onclick> cannot be Tabbed to.
  2. Every input has a label.
  3. Images have alt. Decorative images get alt="" deliberately.
  4. Link text names the destination. "Click here" is meaningless out of context.

Put the mouse down and press Tab. If a control cannot be reached, it does not exist for a real portion of Priya's patients.
