01

Before you touch AI

The ticket is a list problem. Each row looks like { patient, clinician, status }. Status is "open", "done", or "cancelled".

Decide the answers before anyone writes a function. If you cannot say what should come back, you cannot tell whether the agent got it right.

02

Enough JavaScript to defend a diff

A variable is a name for a value. Prefer const. Use let only when the value must move.

const clinicName = "Northline";
let openCount = 0;

const patient = { name: "Priya", status: "open" };
patient.status      // "open"
patient.phone       // undefined — the field is not there. JS does not object.

A function takes input and returns output. That is what makes it testable.

function isOpen(appointment) {
  return appointment.status === "open";
}
Testable

Give it a row, check the boolean. No setup, no globals.

Hard to test

function markOpen() { globalCount = globalCount + 1; } — returns nothing, changes the world.

Use ===. And do not write if (appointment.count) — a count of 0 is falsy, and that is the quiet day at the clinic.

filter, map, reduce — which one the ticket asked for
rows.filter(r => r.status === "open");  // shorter list
rows.map(r => r.patient);               // same length, new contents
rows.reduce((n, r) => n + 1, 0);        // one number

filter changes the length. map changes the contents. reduce produces a single value. A map where a filter belonged returns the right length full of undefined.

None of these three modify the original array. That is a feature. splice is how an agent “filters” and then Priya’s cancelled rows are gone from the source list.

05

Now the agent may improve it

Only after you can defend the behaviour. Improving is not rewriting. The request has to say what must stay true.

Choose the better request · labelled simulation

A safe improvement after your functions pass: clearer names, a shared helper, a comment that states the empty-list rule. An unsafe one: “while I am here” changing what "open" means, or switching to splice because it felt faster.

Engineer's tip. Ask an agent to improve code you cannot yet explain and you will accept a fluent wrong answer. Improve is step nine of the loop, not step one.
