When things fail

The happy path is a demo. Clients pay for the run that happens on a Tuesday when the CRM times out. Retrying is easy. Retrying without doing the side effect three times is the job.

You will be able to
  • Retry a timeout a bounded number of times
  • See why a retry can send three invoices if the write is not guarded
  • Refuse infinite retries
1

Timeout is not 'it failed'

You asked the payment API to charge. The connection dropped. You do not know whether the charge happened. If you retry blindly, you might charge twice. Module 5 solves that with an idempotency key. This module only asks you to bound the retries and watch the side-effect count.

Default n8n/Make mistake: "retry 5 times" on a node that sends email. Five timeouts later the customer has five "your invoice" messages.
