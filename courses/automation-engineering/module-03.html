APIs, webhooks, and auth

You call them. They call you. Neither side should trust a body that is not signed. Most "hacked automations" are just an open webhook URL.

You will be able to
  • Tell an API call from a webhook in one sentence
  • Reject a webhook with the wrong signature
  • Keep secrets out of the graph you would screenshot for a client
1

Two directions

API call: your workflow goes out and asks another system for something, or tells it to do something. You pick the moment.

Webhook: the other system hits a URL you gave it, when they have news. Stripe, Calendly, Typeform — they call you. If that URL has no signature check, anyone on the internet can pretend to be Stripe.

Signature in one picture

The sender and you share a secret. They hash the body with the secret and send the hash in a header. You hash the body with the same secret. If the hashes do not match, you drop the event. You do not "fix" it. Production vendors use HMAC-SHA256. This course's lab uses a smaller teaching hash so you can see match vs mismatch without a crypto library.
