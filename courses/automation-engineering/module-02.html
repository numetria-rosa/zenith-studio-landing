Module 2 · ~45 minutes

Data that moves

Every integration is a translation job. The form says Full Name. The CRM says first_name and last_name. If you map it wrong, you still "built an automation" — you just built a wrong one.

You will be able to
  • Read a nested JSON payload and pull a field out by path
  • Refuse to create a contact when the email is missing
  • Explain why a successful HTTP 200 can still store garbage
1

JSON is just labeled boxes

You do not need to "learn JSON" as a language. You need to walk a path: contact.email means "inside contact, the email field." If the form used Email Address with a space, that path is wrong. Most client bugs are a renamed field, not a broken API.

{
  "id": "sub_88",
  "contact": { "Full Name": "Jordan Lee", "Email Address": "" },
  "source": "google-ads"
}
Rule: a missing email is not "we'll fill it in later." It is a reject. Empty string and missing key are both missing.
2

Lab: map the form or refuse it

Two events will run. The first has an email. The second has an empty email. Your mapping must accept the first and reject the second.
