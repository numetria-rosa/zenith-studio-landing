The brief
Client Northstar Retail, a mid-size multi-category retailer
Role Junior Data Analyst (that's you)
Problem Revenue is up. Leadership is pleased, until Finance flagged that gross profit hasn't grown to match. You've been asked to find out why, and what to do about it.

What the client actually wants to know

  • What is happening to profitability, exactly?
  • Why is it happening?
  • How much is it costing the business?

A

Audit and clean the raw export

Nobody has told you what's wrong with northstar_orders.csv. Find out yourself, the same way you did in Module 4.

Required · real data, real Python, graded

Write audit_and_clean(df). Investigate the raw file, decide what needs fixing, and return {"rows_raw": ..., "rows_clean": ..., "duplicates_removed": ..., "negative_qty_removed": ..., "missing_channel_removed": ...}, all integers.

Stuck for a few minutes? One hint
Three separate problems live in this file: exact duplicate rows, an impossible negative quantity on a handful of rows, and some rows with no channel recorded at all. Category casing is also inconsistent (compare df.category.unique() to what a clean list should look like), but that doesn't change the row count, only the SQL stage cares about it, since the database already has it normalized.
B

Answer it with SQL

The client's question, precisely: which product category is dragging profitability down, and by how much has its margin actually changed? The cleaned data is already loaded into a live database, orders (order_id, order_date, category, channel, quantity, revenue, cogs) and monthly_opex (month, opex).

Explore it yourself · real SQLite, runs in this page
Required · real SQLite, this is the SQL requirement, graded against the live database

Write one query. Return category, a period label of 'H1' or 'H2' (H1 is before 2025-10-01), total revenue, total cogs, and margin_pct ((revenue-cogs)/revenue*100, rounded to 2 decimals), grouped by category and period.

Stuck for a few minutes? One hint
A CASE WHEN order_date < '2025-10-01' THEN 'H1' ELSE 'H2' END expression gives you the period label inline. Group by both the category column and that expression, SUM revenue and cogs per group, then compute the margin from the summed totals, not a row-by-row average.
C

Put a number on it

You now know which category's margin moved, and by how much. The client didn't ask for a percentage, they asked what it's costing them.

Required · real data, real Python, graded

Write quantify_impact(df). Using the cleaned data (clean it the same way as part A inside this function), estimate the gross profit Northstar would have kept in H2 if the category you identified had held its H1 margin rate. Return {"category": "...", "h1_margin_pct": ..., "h2_margin_pct": ..., "estimated_lost_profit": ...}.

Stuck for a few minutes? One hint
"What H2 gross profit would have been at the H1 margin rate" is h2_revenue * h1_margin_pct. Compare that to the actual H2 gross profit (h2_revenue - h2_cogs), the difference is the estimated lost profit.
D

Show it

A number in a sentence is easy to skim past. Build the chart that makes the finding impossible to miss.

Required · real Plotly, real Python, graded

Build a chart of margin % by category, comparing H1 to H2, so the one category that moved stands out against the others that didn't. df is the raw file, already loaded, uncleaned, clean it yourself first.

Stuck for a few minutes? One hint
px.bar(data, x="category", y="margin_pct", color="half", barmode="group") puts H1 and H2 bars side by side for each category, exactly the comparison that makes one outlier category visible.

G

Is this real, or noise?

You explained the finding to a store manager in part F. Before it goes any further, one more check: with only two 6-month windows to compare, could Electronics' margin drop just be normal month-to-month variation, the kind every category has some of?

Why this matters: a real analyst doesn't stop at "the number went down." Module 5 taught you to ask whether a difference is big enough, relative to the natural spread in the data, to trust. This capstone has enough individual orders to actually check that here, not just assert it.
Required · real data, real Python, graded

Write validate_significance(df). Clean the same way as before (drop duplicates, normalize category casing), isolate Electronics, split into H1/H2 by order date, and compute each half's per-order margin percentage ((revenue-cogs)/revenue*100 for each row, not the aggregate). Return {"h1_mean_margin_pct": ..., "h2_mean_margin_pct": ..., "z_score": ..., "is_significant": True or False}, using the standard-error formula from Module 5: se = sqrt(std1**2/n1 + std2**2/n2), z = (mean1 - mean2) / se, and treat abs(z) > 1.96 as significant (the same 95% threshold Module 5 used).

Stuck for a few minutes? One hint
This is per-order margin, not the aggregate revenue/cogs margin from parts B and C, one margin_pct value per row, so you get a real spread (standard deviation) to compare, not just two single numbers.
