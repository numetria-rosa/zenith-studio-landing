Two different kinds of capstone work

This module has two parts, and they're graded differently, on purpose.

Part one, below · auto-graded

One integration exercise. Real messy data, a business question, no steps. Your code runs against the actual file and is checked against the actual correct answer, same as every exercise since Module 2.

Part two, in Projects · self-assessed

Pick one of four full scenarios and produce a real deliverable (a memo, a dashboard, both). This page has no backend, it cannot run your dashboard or read your memo, so that part uses a detailed rubric and sanity checks for your own numbers instead of an automated grader.

Why the split: auto-grading only works when there's one verifiably correct answer to check code against. A written recommendation or a dashboard layout doesn't have one right answer, pretending otherwise would mean either faking the grading or refusing to let you build the parts of this course that most resemble real analyst work. Better to be honest about which is which.
9.1

Integration exercise: the funnel, uncleaned

The dataset: ecommerce_orders.csv, 412 raw order records. Nobody has told you what's wrong with it yet.

Business question: "Of everyone who started an order, how many actually reach each stage, and where's the biggest drop?" The status column records each order's current stage: cart_created, checkout_started, payment, or shipped, in that order.

No steps given on purpose: you already know how to find duplicate rows (Module 4), how to spot a quantity that can't be real (Module 4), and how to build a stage-by-stage funnel (Module 7). This asks you to notice which of those this specific file needs, and in what order, without being told.
Required exercise · real data, real Python, graded

Write funnel_after_cleaning(df). Return {"total": ..., "reached_checkout": ..., "reached_payment": ..., "reached_shipped": ..., "distinct_skus": ..., "biggest_drop_stage": "..."}. Each reached_* value is the count of cleaned orders whose status is at or beyond that stage. biggest_drop_stage is one of "cart_to_checkout", "checkout_to_payment", or "payment_to_shipped", whichever transition loses the largest percentage.

Stuck for more than a few minutes? One hint
Run df.duplicated().sum(), (df.quantity<0).sum(), and df.sku.str.upper().nunique() versus df.sku.nunique() in a scratch cell first, each one tells you whether that specific problem is present in this file at all, before you decide how to handle it.
