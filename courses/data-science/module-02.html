2.1

Variables and strings

A variable is a name you give a value, so you can use it again without retyping it. A string is text, written between quotes.

Why an analyst needs this: every number and label you pull from a dataset needs somewhere to live while you work with it, and every report you write needs to combine numbers and words into a readable sentence.

An f-string (a string with an f right before the quote) lets you drop a variable straight into text:

product = "Outdoor"
amount = 129.9
print(f"{product}: ${amount:.2f}")  # the :.2f means "2 decimal places"
Output: Outdoor: $129.90

2.2

Lists and loops

A list holds many values in order, think of it as one spreadsheet column pulled into Python. A for loop runs the same code once per item in a list.

Why an analyst needs this: a column of 10,000 sale amounts is a list of 10,000 numbers. You almost never process one value at a time by hand, you loop.
sales = [120, 340, 75, 900]
total = 0
for amount in sales:
    total = total + amount
print(total)
Output: 1435

2.3

Dictionaries

A dictionary stores named fields, think of it as one row of a spreadsheet, where each column has a label. You write it as {"key": value, "key2": value2} and read a field with record["key"].

Why an analyst needs this: a single customer, order, or survey response is naturally a dictionary, several named fields belonging to one record. This is exactly what Module 3's pandas rows are built from.
customer = {"name": "Priya", "orders": [42.0, 18.5, 9.0]}
print(customer["name"])
print(sum(customer["orders"]))
Output: Priya
69.5

2.4

Conditions

An if / elif / else chain branches on a condition, the exact same logic as the nested IF formula from Module 1, just written as code instead of a formula.

Why an analyst needs this: Module 1's =IF(B2>1000,"High","Low") only handles two buckets. Real categorization usually needs three or more, and code makes that easy to read.
def classify(amount):
    if amount >= 1000:
        return "High"
    elif amount >= 200:
        return "Medium"
    else:
        return "Low"
classify(1500) → High  ·  classify(500) → Medium  ·  classify(50) → Low

2.5

Functions, start to finish

You've already written five functions above. This section is about naming why: a function packages logic once so you (and everyone reading your analysis) can reuse it instead of retyping the same calculation everywhere.

Why an analyst needs this: "conversion rate" gets calculated constantly, on different datasets, different time periods. Writing it once as a function means you compute it the same correct way every time.
def conversion_rate(visitors, conversions):
    if visitors == 0:
        return 0.0
    return round(conversions / visitors * 100, 1)
conversion_rate(200, 10) → 5.0

2.6

Reading a real CSV file, by hand

A CSV file is plain text: one line per row, values separated by commas. Before you meet pandas in Module 3, you're going to parse one yourself, so pandas.read_csv() reads later as "the thing that automates what I just did," not magic.

The pattern

text.split("\n") breaks a file into lines. The first line is the header, skip it. Each remaining line, line.split(",") breaks it into fields by position. float(field) turns a text number into a real number you can add.

lines = csv_text.split("\n")
header, rows = lines[0], lines[1:]
total = 0
for line in rows:
    if not line.strip():
        continue  # skip a blank trailing line
    fields = line.split(",")
    revenue = float(fields[-1])  # revenue is the last column
    total = total + revenue
