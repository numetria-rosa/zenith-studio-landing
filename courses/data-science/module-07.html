7.0

The three questions a chart can answer

Almost every chart is answering one of three questions. Get this wrong and no amount of polish saves the chart.

Distribution

"What do the values in this column look like, spread out?" Are they clustered, spread wide, skewed, or is there something that shouldn't be there at all? Histogram is the default tool.

Comparison

"How do these categories compare to each other, right now?" Product A vs B vs C, channel vs channel, stage vs stage. Bar chart is the default tool, ranked so the eye doesn't have to hunt.

Trend

"How did this number move over time?" Line chart is the default tool, but only when there's enough underlying signal to be worth connecting the dots, section 7.3 shows a case where it isn't.

Why not pie charts: the human eye is bad at comparing angles and areas, good at comparing bar lengths and dot positions. A bar chart almost always communicates the same comparison faster and more accurately. You won't find one in this module, and the grader will tell you why if you try.

7.3

Trend: when a line chart is the wrong chart

The dataset: the same event log, filtered to purchase events, across 30 days of May.

Business question: "Is there a weekly pattern in when people buy?"

The trap: a daily line chart of 30 noisy points invites you to eyeball a "trend" in what might just be day-to-day noise. The real pattern isn't a trend over time, it's a repeat pattern by day of week, which a daily line is the wrong tool to reveal.
Exercise 3 · real Plotly, real Python, graded

Build two figures: fig_daily, a line chart of purchases per calendar date, and fig_dow, a bar chart of purchases per day of week (Monday..Sunday). df is already loaded and filtered to purchase events with a real datetime column ts.

Hint 1, conceptual
Build both charts even though only one actually answers the question. Comparing them side by side is the point.
Hint 2, technical
.dt.date gives you a calendar date to group daily purchases by. .dt.day_name() gives you the weekday name to group the other way.
Hint 3, code
Both are a value_counts() followed by a chart, exactly like exercise 2, just grouped by a different derived column each time.
Which chart actually answers "is there a weekly pattern"?
7.4

Diagnose and fix a misleading chart

The dataset: marketing_campaign_results.csv, the same 4-channel data from Module 5.

A chart someone on the marketing team already made · real code, run it yourself

This is real, unedited code someone actually wrote. Run it and look at what it shows.

The trap: Referral's conversion rate (9.52%) comes from 21 clicks and 2 conversions. One more or one fewer conversion swings that rate by roughly 5 points. Search's 4.79% comes from 1,815 clicks, barely moves if a handful of conversions go the other way. The chart above treats both numbers as equally trustworthy, they aren't, and nothing about the chart itself warns you.
The fix (same "reliable" rule as Module 5)

A channel's rate is only comparable once it clears a minimum sample: at least 30 clicks and at least 5 conversions. Below that, leave it out of the comparison chart entirely.

Exercise 4 · real Plotly, real Python, graded

Rebuild the chart correctly: filter to reliable channels only, then build the bar chart. df is already loaded.

Hint 1, conceptual
The fix isn't a different chart type, it's different underlying data. Filter before you chart, not after.
Hint 2, technical
Same groupby as the bad chart above, just add a filter: clicks >= 30 and conversions >= 5, both true, before building the figure.
Hint 3, code
reliable = g[(g["clicks"]>=30) & (g["conversions"]>=5)], then chart reliable instead of g.

No step-by-step here: you already know how to standardize a messy column (Module 4) and how to build a trend chart (7.3). This asks you to combine both on a shape you haven't practiced. Q1 = Jan–Mar, Q2 = Apr–Jun, Q3 = Jul–Sep, Q4 = Oct–Dec.
Exercise 6 · real Plotly, real Python, graded

Standardize every period into "YYYY-Q#", sort chronologically, then build a line chart of revenue by quarter. df is already loaded.

Hint 1, conceptual
Three formats map to the same idea. Handle each with its own regex, or its own condition, then fall through to a shared "YYYY-Qn" output.
Hint 2, technical
re.match(r"^(Jan|Apr|Jul|Oct)-\w+-(\d{4})$", period) catches the first format; a similar pattern catches "Q1 2025" and "2025-Q1".
Hint 3, code
Map month-name prefixes to quarter numbers: {'Jan':1,'Apr':2,'Jul':3,'Oct':4}. For the other two formats, the quarter number is already written as a digit somewhere in the string, extract it directly.
