## Why you're learning this

This is where every previous module fuses into one working system. A
neuron's weighted sum is Module 1's dot product. Its transformation of
inputs is Module 2's linear map. Training it is Module 5's gradient
descent, computed via Module 4's calculus. Comparing its output to a
target uses ideas from Modules 8 and 9. There is no new mathematical
object introduced here - only the moment where you watch all of it work
together, on a network small enough to compute by hand.

## 10.1 - One neuron, traced completely

A neuron takes inputs, multiplies each by a weight, adds them up (plus a
bias), and passes the result through an activation function. That's the
entire forward pass. Comparing the result to a target number gives a loss.
Backpropagation then asks: for each weight, how should I nudge it to make
that loss a little smaller?

<Callout tone="info" label="Definition">
**Forward pass**: inputs → weighted sum (z) → activation (a) → compared to
a target → loss. **Backward pass**: starting from the loss, apply the
chain rule step by step backward through the same computation, producing a
gradient for every weight. **Gradient descent** then updates every weight
using that gradient, exactly as in Module 5.
</Callout>

<Callout tone="info" label="Worked example">
Trace the forward pass by hand for a neuron with $x_1=1, x_2=2, w_1=0.5,
w_2=-0.5, b=0.1$, using $\sigma(z) = 1/(1+e^{-z})$:
1. Weighted sum: $z = w_1x_1 + w_2x_2 + b = (0.5)(1) + (-0.5)(2) + 0.1 = 0.5 - 1 + 0.1 = -0.4$
2. Apply the activation: $a = \sigma(-0.4) = 1/(1+e^{0.4}) \approx 0.401$

So this neuron outputs about $0.401$ for these inputs and weights - you
can build this exact configuration in the lab below and confirm the
displayed $a$ matches.
</Callout>

## 10.4 - Where this shows up in real machine learning

- **This is literally what training is.** A real network repeats this
  forward-pass/backward-pass/update cycle across every neuron, every
  layer, and every training example, millions of times.
- **Automatic differentiation** (the engine behind PyTorch, TensorFlow,
  and JAX) is software that performs exactly the chain-rule bookkeeping
  from this module automatically, for arbitrarily large networks, so
  nobody has to hand-derive gradients for a billion-parameter model.
- **Vanishing/exploding gradients**, a real and important training
  problem in deep networks, comes directly from chaining together many
  multiplicative terms (as in this module's chain rule) - if each term is
  consistently a bit less than 1, the product shrinks toward zero across
  many layers; if consistently more than 1, it grows explosively.

## 10.5 - A failure mode this prevents

<Callout tone="warning" label="Common mistake: treating a neural network as an unknowable black box">
"Neural networks are black boxes" is a common claim, but the mathematics
inside one neuron is fully traceable, as this lab just demonstrated. A
large network is not a different KIND of mathematics - it's this exact
same forward/backward loop, repeated at scale. Knowing that means a
training problem (loss not decreasing, gradients vanishing, weights
exploding) is something you can reason about mechanically, not just a
mysterious malfunction.
</Callout>

<Callout tone="warning" label="Common mistake: expecting one gradient step to fix everything">
A single call to "Step" nudges every weight a small amount in the
locally-correct direction - it does not jump straight to the optimal
weights, even for this one tiny neuron. Real training runs many thousands
of these small updates, and expecting visible convergence after a
handful of steps (then concluding "this isn't working" when the loss is
still nonzero) is a common and avoidable source of premature
troubleshooting - the lab's own loss history, tracked step by step, is
exactly the right thing to watch instead of the raw loss at any one
moment.
</Callout>
