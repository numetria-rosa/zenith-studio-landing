## Why you're learning this

Real data is almost never spread out evenly in every direction. Height and
weight move together. So do "hours studied" and "exam score," or hundreds
of the numbers inside a language model's embeddings. This module answers a
concrete question: **given a cloud of correlated data, which direction
actually matters most, and how much would you lose by keeping only that
one?** The answer - eigenvectors and eigenvalues of the data's covariance
matrix - is one of the most reused ideas in all of machine learning:
dimensionality reduction, PCA, and (later, in Module 11) even part of how
attention works all come back to this same question.

## 3.1 - The direction that doesn't bend

In Module 2, you saw a matrix bend a square into a slanted parallelogram.
Almost every direction gets turned somewhere new. But for (almost) every
matrix, a small number of special directions don't turn at all - a vector
pointing that way just gets longer or shorter, still pointing exactly the
same way (or exactly the opposite way).

<Callout tone="info" label="Definition">
An **eigenvector** of a matrix is a direction that transformation doesn't
rotate - only scales. The amount it scales by is the matching
**eigenvalue**. For a cloud of data, if the matrix is the data's
**covariance matrix** (how much each pair of variables moves together),
the eigenvectors point along the directions the data is actually spread
out in, and the eigenvalues tell you exactly how much spread lives in each
one.
</Callout>

<Callout tone="info" label="Worked example">
A covariance matrix $S = \begin{pmatrix} 4 & 0 \\ 0 & 1 \end{pmatrix}$ is
already diagonal - the easiest case to compute by hand.
1. For a diagonal matrix, the eigenvalues are simply its diagonal entries: $\lambda_1 = 4$, $\lambda_2 = 1$
2. Their eigenvectors are the plain axis directions $(1,0)$ and $(0,1)$ - no rotation needed
3. Variance explained by PC1: $\dfrac{\lambda_1}{\lambda_1+\lambda_2} = \dfrac{4}{5} = 80\%$

So this data is spread 4 times more along the x-axis than the y-axis, and
keeping only PC1 would preserve 80% of its total variance. You'll see this
exact case in the lab if you set the rotation to 0° with an elongated
cloud.
</Callout>

## 3.4 - Where this shows up in real machine learning

- **Dimensionality reduction for visualization**: embeddings from a real
  model can have hundreds of dimensions - PCA finds the 2 or 3 directions
  that preserve the most real structure, so a scatter plot is as
  informative as a flat plot can be.
- **Noise reduction**: directions with very small eigenvalues often
  represent measurement noise rather than real signal - dropping them can
  make downstream models more robust, not just faster.
- **Feature compression**: instead of feeding a model hundreds of raw,
  correlated features, PCA can compress them into a much smaller number of
  effectively independent (uncorrelated) directions that capture almost
  all the same information.

## 3.5 - A failure mode this prevents

<Callout tone="warning" label="Common mistake: applying PCA and assuming nothing was lost">
"Variance explained" is not "information preserved" in every sense that
matters. A direction with tiny variance can still carry a rare but
critical signal - a fraud-detection dataset where 99.9% of the variance is
"normal transaction noise" and the fraud signal lives entirely in the last
0.1% is a real, common failure mode: PCA would happily discard exactly the
direction you needed most. Always ask what a discarded direction might
represent before assuming smaller-variance means safe-to-drop.
</Callout>

<Callout tone="warning" label="Common mistake: expecting PCA's directions to have an obvious meaning">
Each principal direction is a mathematical combination of the original
features (a mix of "how much x" and "how much y"), not automatically a
meaningful, nameable concept on its own. In a real dataset with many
features, PC1 might turn out to be "roughly 70% feature A plus 30%
feature B" - a real, useful direction of maximum spread, but not
something you should expect to always have a clean, human-readable label
like "overall size" just because it happens to work out that way in
textbook examples. Sometimes it does; often it takes real domain
investigation to interpret what a given principal direction represents.
</Callout>
