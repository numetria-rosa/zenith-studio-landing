When a model "calls a tool," it doesn't execute code, send a network request, or touch a database. It produces text, a structured description of what it wants to happen: a tool name and a set of arguments. Your code reads that description, decides whether to trust it, and only then actually does the thing.

<Def title={"Definition: tool call"}>

A structured request produced by a model, naming a specific tool and providing arguments for it, e.g. `{ name: "get_weather", arguments: { location: "Paris" } }`. It's a proposal, not an action, until your code executes it.

</Def>

This distinction matters because it means every tool call is, structurally, the same kind of thing as Module 1's raw model output: text that claims a certain shape, generated by a system that can be wrong, and that must be checked before you act on it.
