## What this module is, and isn't

Every prior module taught one idea in isolation. This one teaches nothing new, it asks whether you can put seven ideas together under one brief without dropping any of them, which is the actual job. There's no new theory here, just the same rigor applied to a single realistic scenario end to end.

## How grading works here

This module replaces the usual multiple-choice checkpoint with three real deliverables, graded from what you actually submit, not from boxes you tick yourself. Part 1 inspects the actual text of your design document for the specific technical content each section needs. Part 2 runs real automated tests against code you write, combining retrieval and idempotent tool execution. Part 3 checks your diagnosis of a real bug against the actual failure mode. Part 4 combines all three into one score.

## How to work through it

1. Read the brief carefully, twice, most real design failures come from missing a stated requirement, not from getting the theory wrong.
2. Write your design document directly into Part 1's fields, then check it, and fix whatever comes back flagged.
3. Complete the implementation in Part 2 and run the tests until they pass. A red test tells you exactly which behavior is wrong.
4. Diagnose the bug in Part 3, then compare against the reference solution outline afterward, not to copy it, but to see how the same requirements can be satisfied a different valid way.
